# Short-Order Showdown (Bevy cooking game) — Step 8 done

Real cooking game, Bevy 0.16, ~8900 lines, 54 game tests + 3 server tests.
KayKit glTF + kitchen SFX + Kevin MacLeod music + procedural menu art.

## Run

```sh
sudo apt-get install -y libasound2-dev libudev-dev pkg-config
cargo run -p cooking-game
cargo test -p cooking-game   # 54 tests
```

## Step 8: server + textures (this step)

- **Leaderboard server** (`/server`, Axum): `GET /health`, `GET /` (HTML table),
  `GET /api/scores?level=&limit=`, `POST /api/scores` (validated, ranked,
  JSON-file persisted, CORS open). `render.yaml` + `server/Dockerfile` deploy it
  to Render: `render blueprint launch --file render.yaml`. See `server/README.md`.
- **Game posts scores**: background thread on every LevelComplete (never blocks),
  top-5 fetched + shown live on the results screen, offline-safe fallback.
  Point it at deploy via `LEADERBOARD_URL=...` or `server=...` line in save.txt.
  Stable install tag auto-generated (`Chef-XXXX`).
- **Textures**: procedural license-clean PNGs (`gen_textures.py`, stdlib only) —
  warm `menu_bg.png` behind all menu/shop/settings/brief screens, golden
  `results_bg.png` behind results. KayKit's own `restaurantbits_texture.png`
  was already on all 3D models.

## Honest state of "finished"

Systems: complete and deep (7 recipes, 3 restaurants, minigames, economy,
upgrades, clients, persistence, online board). Presentation: improved but still
programmer-grade — flat-color UI over one backdrop, capsule customers, no
character animation, no food icons, no skinned meshes. What would make it look
like a real cooking game: illustrated UI theme + food icons, animated chef
(GLTF rig), plated-dish close-ups, lighting/post polish pass, juice (screen
shake, aroma trails). Those are art tasks, not systems tasks.

## Controls (defaults, all rebindable in Settings)

WASD/arrows move | E/Space interact-chop-stir | Q/X trash | R rescue | Esc/P pause | M mute.
